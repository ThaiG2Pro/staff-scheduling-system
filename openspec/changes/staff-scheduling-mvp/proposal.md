# Proposal for staff-scheduling-mvp

## Acceptance Criteria

- **AC-01** [CONFIRMED]: Schedule, Staff & Shift Template Management (F-01..F-03, E-08..E-09) — Ref: docs/01-product-scope.md, docs/03-domain-model.md (§2-§5), docs/technical-design.md (§2, §5). Includes previewDeleteStaff/previewDeleteShift (returns affectedAssignmentsCount) and ShiftTemplate time edit ripple-effect (preserves assignments/pins across 7 days, converts hour/overlap violations to soft warnings).
  GIVEN a Store Manager manages weekly schedules WHEN creating/editing schedules, staff (with maxWeeklyHours & live assigned/max meter), and shift templates (seeded 07:00-15:00 & 15:00-23:00, supporting overlapping shifts) THEN changes sync immediately across roster and summary with previewDeleteStaff/previewDeleteShift cascade confirmation and soft warnings on template edits.

- **AC-02** [CONFIRMED]: CSV Transaction Importer & Mon-Sun Normalization (F-08, E-01, T-03..T-05) — Ref: docs/03-domain-model.md (§2.6), docs/technical-design.md (§6). Pure parseCsvTransactions(text) handles UTF-8 BOM, RFC 4180, Weekday-only vs UTC Calendar-date headers (no mixing), safe integers, and atomic preserve-on-error.
  GIVEN a transaction CSV file (7am-10pm, any weekday or calendar-date order like Fri-Thu) WHEN imported via parseCsvTransactions THEN it normalizes columns to Mon-Sun, validates 7 days x 16 hours non-negative safe integers, and on error preserves existing demand data without overwrite.

- **AC-03** [CONFIRMED]: Exact BigInt Decimal Math & 2-Stage Deterministic Auto-Scheduler (F-04, F-07, E-03..E-04, T-01..T-02, T-09..T-13) — Ref: docs/04-optimization-spec.md (§1-§6), docs/technical-design.md (§3-§4). 100% Pure TS in src/domain/, computeRequiredStaff via BigInt fraction ceiling, Stage 1 Best-Fit + Stage 2 O(1) Delta Rebalance, returning UI-friendly AutoScheduleDiagnostics (shortageHours, uncoverableRequiredStaffHours, residualCoverableShortageHours, unusedCapacityHours, overstaffedHours, summaryMessages) & PinConflict[].
  GIVEN demand transactions and targetTxnsPerStaffHour N in [1, 500] WHEN computing required staff and running 2-stage Auto-schedule (Best-Fit + O(1) Delta Rebalance) THEN BigInt exact ceiling division prevents IEEE-754 drift, F-04 hard constraints and pinned assignments are respected, pin conflicts block execution cleanly, and UI-friendly diagnostics (unfilledHours, unusedCapacity, pinConflicts) are returned deterministically.

- **AC-04** [CONFIRMED]: Weekly Roster, Pinning & Assignment Guidance Popover DTOs (F-05, F-07, E-05..E-07) — Ref: docs/02-manager-workflow.md, docs/03-domain-model.md (§4, §6.2-§6.3), docs/05-ux-spec.md. constraints.ts returns pre-grouped { eligible: GuidanceCandidate[], requiresAttention: GuidanceCandidate[] } with reasons[] and remainingHours; Reassign resets isPinned=false.
  GIVEN a Weekly Roster in Shift-first layout WHEN Manager clicks to assign/swap/remove staff or pin assignments THEN AssignmentGuidancePopover provides pre-grouped eligible[] and requiresAttention[] DTOs with reasons[] and remainingHours, allowing soft-warning overrides and 2-click sick-leave replacement.

- **AC-05** [CONFIRMED]: Aggregated Summary 7x16, 4 Schedule Health Signals & Conditional P1 Coverage View (F-06, F-09, T-06..T-08) — Ref: docs/03-domain-model.md (§6.1, §6.4-§6.5), docs/04-optimization-spec.md (§5), docs/05-ux-spec.md. Union-of-hours staffHours/assignedHours, 3 metrics/cell + 4 weekly totals, 4 independent Health Bar signals evaluated on unrounded floats, P1 Coverage View gated behind P0 exit.
  GIVEN any schedule state mutation WHEN deriving schedule metrics THEN AggregatedSummaryView displays 7x16 cells (Transactions, union-of-hours Staff hours, Txns/staff hour) + 4 weekly totals, ScheduleHealthBar updates 4 independent signals (Staffing Gaps, Hour Limit Warnings, Demand Coverage, Jain Fairness Index), and conditional P1 Coverage View toggles delta display after P0 exit gate.

- **AC-06** [CONFIRMED]: LocalStorage 4-Mode Defense, Realistic Demo Store & Performance Benchmarks (F-10, T-14..T-15, M-01..M-10) — Ref: docs/03-domain-model.md (§7), docs/technical-design.md (§5, §8, §9), docs/06-acceptance-tests.md. Bootstrap outside StrictMode, 4 storageModes + Atomic Reset Contract, realistic demoData (sample CSV + 8-10 staff 16h-40h), Vitest Bench & Playwright Chromium benchmarks.
  GIVEN client-side persistence via window.localStorage WHEN bootstrapping outside React Strict Mode or auto-saving THEN 4 storage modes (normal, recovery_locked, incompatible_version_locked, storage_unavailable_locked), Atomic Reset Contract, realistic Demo Store (CSV sample + 8-10 staff 16h-40h), and benchmarks (Vitest Bench + Playwright Chromium) pass 100% of T-01..T-15 and M-01..M-10.
